## Path

Tech career started with an AAS in Networking in 2004. Help desk and Active Directory paid the bills briefly; I wanted to *build* systems, not only keep tickets moving.

I’ve been building websites professionally since **2006**. The next decade was self-taught PHP, Python, SQL, and C# in production. In 2013 I went back for a BS in CIS with a hard focus on web development (the code side). That finished in **2015** with Objective-C, modern JavaScript, and formal project management — all while working full-time for the same employer I’ve been with since **2010**.

Since then the catalog has gotten large: WordPress, Drupal, Magento, Episerver, Concrete CMS; MEAN, Rails, PHP and C# frameworks; Linux and Windows servers; NGINX and Apache; MySQL, MSSQL, PostgreSQL, MongoDB. A few mobile experiments I don’t miss. The through-line is the same — keep live systems honest, then modernize when the business is ready.

## How I usually work

Stabilize first. Inherited stacks rarely need a greenfield rewrite on day one. Uptime, backups, query performance, and patching come before a fashionable front end.

Then bridge. Keep years of content and business logic; put a maintainable edge in front when speed or security demands it.

Write it down. Docs, ingest URLs, and operator notes matter as much as the demo — Prompt Studio and ThermalTrace both carry that habit.

Legacy repair and stack modernization, Linux/Windows server maintenance, MySQL/MSSQL administration, and technical audits — plus product work like Prompt Studio and ThermalTrace when those patterns apply.

No. Most useful engagements start with what’s already running: stabilize, measure, then modernize in slices. Greenfield happens when the old stack truly can’t carry the next year.
